How to use it

Setting it upSetting it up

  1. Connect

    We set it up with you when you join: the daily Amazon import, and which rota code each route type carries.

  2. You

    Someone on your team signs in to Amazon Logistics Scheduling on that browser at least once a day.

  3. Automatic

    Each morning Connect pulls yesterday from Amazon’s Work Summary and checks every route against your rota.

Then each morning:

  1. 1

    Open Plan › Rota Validation. It opens on yesterday, with the To fix list first; use ‹ › to step between days.

  2. 2

    Tap any line for Amazon’s record: Transporter ID, parcels delivered and returned, and check-in and check-out times.

  3. 3

    Press Link on an Unknown TID and pick the driver, or Re-link… a driver whose stored Transporter ID is out of date.

  4. 4

    Correct a Wrong route type on Plan › Rota, then read Validated as confirmed: the driver paid is the driver Amazon saw.

It won’t
  • Change the rota or pay, or hold a pay run. It only reports: pay is still worked out from the rota.
  • Check a rota code you haven’t mapped. Ride-alongs, POC and training are never checked, so never red.
How does this connect to pay?

Pay is worked out from the rota: the day code on each driver’s day prices their pay. So Validated means the driver paid for that route is the one Amazon says ran it, on the route type the rota prices. A red line is a pay question, caught before the pay run: Wrong route type is the wrong rate, Not on rota is work Amazon saw that the rota doesn’t price as a route, and Not on Amazon is a rota day Amazon has no route for. A rescue is one day worked, never paid twice. Rota Validation never changes pay itself.

What happens each day?

Once someone on your team has signed in to Amazon Logistics Scheduling in that browser, the import runs each morning and reads the last 7 days, because Amazon keeps editing a day until it’s signed off. Routes not yet signed off show amber. If no import has arrived for 24 hours, the page says so.
